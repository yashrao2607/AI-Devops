PART 6 — INTELLIGENT CHUNKING
========================================================

This is one of the most important parts of Phase 2.

Do NOT use only:

"every N characters"

Implement repository-aware chunking.

For source code, prefer boundaries such as:

- class
- function
- method
- module
- logical blocks

For Markdown:

- headings
- paragraphs
- sections

For configuration:

- logical YAML/JSON/TOML sections
- related key groups

For Docker files:

- instruction blocks

For CI/CD YAML:

- job
- step
- workflow sections

When semantic parsing is unavailable:
use safe fallback chunking.

Every chunk MUST retain source information.

Required metadata:

- chunk_id
- repository_id
- commit_sha if available
- file_path
- language
- category
- chunk_type
- line_start
- line_end
- file_size
- content_hash

The chunk content must correspond to the recorded lines.

Do not invent line numbers.
