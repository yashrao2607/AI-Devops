## 27-Step Demonstration Sequence

### Step 1: Open GitHub Repository
- **Action**: Open the GitHub repository in browser.
- **Narrative**: *"Welcome professors. Here is our public repository. Notice the clean structure: backend FastAPI service, React Vite frontend, documentation, and the `.github/workflows/deploysafe.yml` pipeline."*

### Step 2: Show DeploySafe Dashboard
- **Action**: Switch browser to `http://localhost:5173/#overview`.
- **Narrative**: *"This is the DeploySafe web platform. It communicates immediate deployment intelligence: total repositories indexed, recent audit runs, and system health status."*

### Step 3: Show Current Baseline
- **Action**: Click into the historical runs table or inspect baseline metrics.
- **Narrative**: *"Notice our repository baseline. In its initial clean state, our demo repository has a low risk score. Now we will simulate a real developer workflow introducing high-risk deployment regressions."*

### Step 4: Make a Controlled Risky Change
- **Action**: In `demo-repos/deploysafe-rag-demo/config.py` or `server.py`, introduce:
  1. An unconfigured environment variable: `API_KEY = os.environ["STRIPE_PRIVATE_KEY"]` without defining it in `.env.example`.
  2. A hardcoded root user in `Dockerfile`: `USER root`.
- **Narrative**: *"As a developer, I am adding Stripe payment processing. However, I forgot to declare the environment variable in configuration manifests and switched our container to root user. Standard CI passes this easily."*

### Step 5: Open/Update Pull Request
- **Action**: Commit and push the branch or trigger CLI analysis:
  `python -m backend.app.cli analyze --target demo-repos/deploysafe-rag-demo --ci`
- **Narrative**: *"The developer opens a Pull Request. GitHub Actions intercepts the commit."*

### Step 6: Show GitHub Actions Workflow
- **Action**: Show `.github/workflows/deploysafe.yml` executing the DeploySafe CLI action.
- **Narrative**: *"The action runs DeploySafe in CI mode. Notice the deterministic gate evaluation running."*

### Step 7: Show DeploySafe Analysis Flow
- **Action**: Switch to the DeploySafe UI (`#analyze` tab or view live telemetry).
- **Narrative**: *"Behind the scenes, the DeploySafe Orchestrator initiates execution."*

### Step 8: Show Orchestrator Planning
- **Action**: Show the dynamic `AnalysisPlan` generated by the orchestrator.
- **Narrative**: *"The orchestrator inspects discovered file categories (code, Docker, config) and dynamically plans tasks: code_analysis, configuration_analysis, security_analysis, and documentation RAG."*

### Step 9: Show Specialized Agents Running in Parallel
- **Action**: Highlight the agent telemetry grid (Code Agent, Config Agent, Security Agent, RAG Agent).
- **Narrative**: *"Specialized agents run concurrently in worker threads. Each agent is strictly bounded to its designated domain."*

### Step 10: Show RAG Retrieval Context
- **Action**: Show the retrieved documentation context from ChromaDB.
- **Narrative**: *"The Documentation RAG Agent queries the vector store, retrieving the repository's setup guide which mandates that all environment variables must be declared in `.env.example`."*

### Step 11: Show Deterministic Tool Usage
- **Action**: Point to the tool execution counter (`get_file_content`, `docker_check`, `get_dependency_manifests`).
- **Narrative**: *"Agents do not guess lines. They invoke deterministic tools that inspect exact file lines."*

### Step 12: Show Candidate Finding Aggregation
- **Action**: Show the raw candidate findings pooled before reflection.
- **Narrative**: *"Agents report 3 candidate findings. Now the critical validation phase begins."*

### Step 13: Show Adversarial Critic Reflection
- **Action**: Highlight Critic status and decisions (`VALIDATED`, `NEEDS_REVIEW`).
- **Narrative**: *"The Critic Agent reviews each candidate. It checks whether the file exists, validates line boundaries, and checks for duplicates. Any hallucinated file or line is rejected with zero points."*

### Step 14: Show Deterministic Risk Engine Evaluation
- **Action**: Click on the risk score and open the `Deterministic Risk Formula` dialog.
- **Narrative**: *"DeploySafe does NOT use an LLM to generate the final risk score. The mathematical Risk Engine calculates the score deterministically using strict severity weights: Critical=35, High=25, Medium=15, Low=7."*

### Step 15: Show Final Authoritative Score & Gate Status
- **Action**: Show the calculated score: e.g. `75 / 100` (`HIGH RISK`).
- **Narrative**: *"The deterministic score is 75/100. Because this exceeds the policy threshold of 50, the gate evaluates to BLOCKED / REVIEW REQUIRED."*

### Step 16: Show GitHub Gate Result & PR Comment
- **Action**: Show the generated Markdown comment or CLI exit code (`exit code 1`).
- **Narrative**: *"In GitHub, the PR status check turns red. An automated, formatted PR comment is posted with exact line citations and remediation instructions."*

### Step 17: Open Finding Detail
- **Action**: In the Findings UI, click to expand the finding: *"Missing Environment Variable STRIPE_PRIVATE_KEY"*.
- **Narrative**: *"Let's drill into the finding details."*

### Step 18: Show Actual Repository Evidence
- **Action**: Point to the exact code snippet viewer with highlighted line number and file path.
- **Narrative**: *"Notice the evidence: exact file path, exact line number, and raw snippet. Zero synthetic code."*

### Step 19: Show Actionable Recommendation
- **Action**: Read the remediation section.
- **Narrative**: *"DeploySafe provides an actionable fix: 'Add STRIPE_PRIVATE_KEY to .env.example with descriptive documentation and fallback handling in config.py'."*

### Step 20: Fix the Issues
- **Action**: In `demo-repos/deploysafe-rag-demo`:
  1. Add `STRIPE_PRIVATE_KEY=` to `.env.example`.
  2. Change `USER root` to `USER appuser` in `Dockerfile`.
- **Narrative**: *"We now implement the exact recommendations."*

### Step 21: Push New Commit
- **Action**: Commit and trigger re-analysis.
- **Narrative**: *"The developer pushes the fix commit."*

### Step 22: Show Action Rerun

- **Narrative**: *"CI re-evaluates the updated commit."*

### Step 23: Show DeploySafe Rerun
